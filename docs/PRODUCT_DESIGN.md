# 『世界のささやき（World Whisper）』アプリケーション設計方針

> 新たな視点と内なる自分が交差する、セレンディピティの補助線。

## 1. 定義
これは観光情報を提供する案内アプリではない。ユーザーがいる場所・時間・状況に応じ、予期せぬ発見をもたらし、世界を見る新しい視点をそっと提示する「レンズ」である。

### 本質的価値
- **世界の再発見**：日常や再訪した場所にも、まだ見えていない意味を見つける
- **対話の媒介**：AIが答えを与えるのでなく、世界と内なる自分の間に入る
- **内なる自分との対話**：外からのささやきが、感情・記憶・考えを呼び起こす

構造は **世界（背景・歴史・流動）→ AI（解釈・ささやき）→ 内なる自分（気づき・内省）**。AIは知識を誇示せず、「こう見ると面白いかもしれない」という補助線になる。

## 2. 文脈理解
同じ物理的な場所も、時刻、天候、季節、移動の流れ、経験と関心で意味が変わる。位置情報だけではなく、次の文脈を扱う。

- **短期エピソード**：SDK位置情報、時刻、天候・気温、位置の安定・文脈変化・滞在時間。徒歩・車などの移動形態はSDKから直接取得できる前提にせず、必要性と取得手段を後続検証する
- **長期セマンティック**：歴史・港湾文化・建築・自然などの興味、過去に反応した視点
- **空間・歴史的背景**：地点の歴史、地理的特徴、文化や人・物の流動

## 3. 入出力体験
入力はGPS、時刻、天候、季節、移動経路、滞在時間、興味、タッチを基本とする。音声はSDK標準機能で低遅延かつ安全に利用できる場合の将来拡張とし、初期価値は「対象を認識すること」ではなく「意味を発見すること」に置く。

出力はG2に表示する**一つだけの短い視点**。完全自動通知ではなく、端の控えめなアイコンや弱い振動で候補を示し、興味がある時だけ深掘りする。

例：単なる「博多港は国際港です」ではなく、「今見えている船の流れは、昔から続く福岡と島・大陸をつなぐ海の道の一部です」。

## 4. 生成原則
LLMは50文字以内の日本語1文で、解説・長文・断定を避ける。場所、時間、天気、移動、興味を解釈し、周囲を見渡すか思考を深めたくなる新しい視点・問いかけを一つ生成する。

## 5. UI/UX
- 通知：移動・滞在などの文脈変化を自動検知し、控えめなアイコンと微弱振動で「気づきのヒントがあります」とだけ伝える
- 表示：576×288領域、単色、50文字以内の1〜2文とし、無操作なら5秒で自動消灯する
- シングルタップ：ささやき表示中は「この場所の背景」「別の見方」「自分への問い」の深掘り候補を開き、候補表示中は選択を決定
- 後方／下スライド：別の視点を生成
- 前方／上スライド：飛ばす／閉じる／クリア
- 候補表示中の後方／下スライド：次の候補へ移動
- ダブルタップ：SDKが安全な終了操作を提供するまで開発用終了
- 音声入力：外部STTを中核依存にせず、SDK標準の音声認識と安全な終了操作が利用可能になった時点で再評価
- 意図：読むことや操作に注意を奪われず、すぐ現実世界へ視線を戻す

Phase 2の開発中は、本番仕様を変えずに、パッシブ通知をスマホ画面の「通知を発生」、5秒自動消灯を「表示を消す」ボタンで代替する。まずG2表示と操作状態を決定的に検証し、その後に文脈の自動検知と5秒タイマーを接続する。

Phase 2 v0.9.0では選択式深掘りを正式な基本UXとする。音声認識は任意の将来拡張とし、入力方式に依存しない`DeepenIntent`へ変換して既存生成器へ接続する。

## 6. アーキテクチャ
Even G2（BLE）→ スマートフォン／Even App Plugin（GPS・時刻・速度・音声・描画）→ HTTPS/WebSocket → Context Backend（文脈構築・ナレッジ検索）→ 外部LLM API。

クライアントはTypeScript／Even Hub SDKを基本とし、UIが複雑化した場合にReactを導入する。バックエンドはFastAPIまたはNode.js。長期的には反応履歴を使う長期記憶と位置連動ナレッジを追加する。

クライアント内部では、Even Hub SDKの実機差を吸収するアダプター、アプリ状態、G2表示、診断UI、文脈取得、ささやき生成を分離する。Phase 1では `ContextSnapshot → WhisperGenerator → G2表示` を基本フローとし、最初はルールベース生成、後からHTTPSバックエンド経由のLLM生成へ置き換える。APIキーや位置履歴はGitHub Pagesのクライアントへ保存しない。

端末・OSに密接な機能はSDK-firstを原則とし、Even Hub SDKに標準機能がある場合は自前実装より優先する。アプリ固有コードはSDKアダプターと文脈解釈へ限定し、位置更新のスケジューリング、距離フィルター、開始・停止はSDKへ委ねる。Google Maps Platformなどの外部APIは移動検出ではなく、周辺施設や場所の意味づけが必要になった段階で、クライアントへAPIキーを置かないバックエンド構成として検討する。

位置情報はブラウザ標準APIではなく、`location`権限を宣言したEven Hub SDKの`getAppLocation()`から明示操作時に1回取得する。raw位置情報はPhase 1では保存・外部送信せず、メモリ上の`ContextSnapshot`としてのみ扱う。権限プロンプトは`.ehpk`のPrivate Buildで検証する。

## 7. 段階開発
1. **PoC**：スマホ単体で位置情報＋LLM、手動トリガーで1文を表示・音声出力
2. **G2連携**：G2描画、控えめな通知、速度・滞在時間、文字数とレイアウト最適化
3. **パーソナライズ**：深掘り／無視の反応履歴、長期記憶、位置連動ナレッジ
